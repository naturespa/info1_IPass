# 情報Ⅰ ITパスポート CBT — info1_IPass

`pycbt`の表紙と`info1_ddl_public`のCBT画面を参考にした、学校向けITパスポート学習サイトです。紺・クリーム・黄を使い、文字と操作の境界が読み取りやすい配色にしています。

## 収録内容

令和8・7・6・5・4・3年度、令和2年度秋期、令和元年度秋期、平成31年度春期、平成30・29・28年度の春期／秋期。**15回 × 100問 = 1,500問**です。問題と選択肢・図表はIPA公開問題PDFから切り出し、解答は公式正解を使用しています。分野は各回の公式問題冊子の区分に沿っています。

指定されたITパスポート試験ドットコムの独自解説や画像は転載せず、復習時に該当する解説ページへリンクしています。詳しくは[出典画面](sources.html)、取得先は[scripts/sources.json](scripts/sources.json)、原本のハッシュは[data/catalog.json](data/catalog.json)を参照してください。

## 利用方法

- 授業用：各回75問固定・45分。ストラテジ26問・マネジメント15問・テクノロジ34問。URLの旧問題数指定があっても、新規の授業用受験は75問。開始済みの受験と過去の記録は元の問題数を保持。
- 授業用は全15回から各5問を抽出。分野配分を守り、分野ごとの年度配分も可能な限り均等にします。番号・実施回・ブラウザの暗号学的乱数で作る128ビットの抽選値を使い、問題の順序も毎回変更。本人の過去の出題ID（中断した受験を含む）を除外し、5回375問の重複を防ぎます。生徒間で個別の問題が一部重なることはあります。
- 抽選方法・乱数値・実施回・除外IDと、確定した出題IDをブラウザ／履歴JSONに保存。再開で再抽選しません。年度別練習は原本固定。練習は再出題を許可し、回数制限はありません。
- 本チャレンジの抽選時点で、本人の練習既出問題との重複を75問中最大11問（15%以内）にします。年度・分野の配分は維持。本チャレンジ同士は重複禁止です。終了後の誤答復習はこの上限の対象ではありません。過去の練習でほぼ全問を見ている場合など、未練習問題が不足して条件を満たせないときは、上限を無断で緩めず案内を表示します。これは練習回数を制限するものではありません。
- 問題の実測正答率や難易度ラベルは収録されていません。年度・分野の均等抽出で難易度の偏りを抑えますが、各回の難易度が同一であると保証する方式ではありません。
- 年度別模擬試験：原本の順番・分野数をそのまま使用して100問・120分。
- 分野別練習：10／20／35／50／75／100問、1〜180分。出題対象が少ない場合はエラーを表示。
- 受験番号4桁・氏名を入力 → 確認 → 操作説明 → 試験開始。
- 解答保存、見直し印、解答一覧、白黒反転、表示倍率、原本の参考資料に対応。
- 再開しても期限は延びません。時間切れで自動採点します。
- 全分野ランダムは[IPAの出題比率](https://www3.jitec.ipa.go.jp/JitesCbt/html/about/range.html)35：20：45に配分。端数は最大剰余法で調整。100問なら35・20・45問、75問なら26・15・34問。指定年度で不足する場合は全15回を選択。
- 本チャレンジは1人（受験番号ごと）5回まで。「試験開始」で1回を使用。開始前の取消し・再開では増えず、開始後の中断終了は1回に数えて記録を保持。練習・年度別練習・誤答復習の回数は本チャレンジと別管理で無制限。5回終了後も練習できます。旧混在履歴はモードごとに回数を移行します。
- ステータスに各回の状態・条件・総合／3分野の正答率・正解数を表示。同条件（モード・問題数・時間・分野）の終了記録をグラフで比較し、初回から最新回への伸びをポイントで表示。中断終了は比較から除外。問題・年度の難易度差があるため学習の目安。
- 履歴JSONの保存・読込・学校サーバへの送信、比較用CSV保存に対応。結果画面の単回JSON・印刷・復習リンクも使用可能。

受験回数・解答・成績の保存は従来どおりブラウザのlocalStorageです。学校サーバは提出用だけで、受験を管理しません。5回制限は同じ端末・ブラウザ・サイト内の記録に対して適用します。データ削除や別端末での回数の強制はできません。履歴JSONの読込で回数・受験中データを引き継げます。同じ端末・ブラウザから再開してください。ブラウザデータ削除・シークレットモード終了で消えます。通信切断時も、既に読み込んだ問題で解答できますが、未読の画像や外部解説には接続が必要です。

## GitHub Pagesで公開

このリポジトリはビルド不要の静的サイトです。

1. GitHubの **Settings → Pages** を開く。
2. Sourceを **Deploy from a branch**、Branchを **main / (root)** にしてSave。
3. 公開先：`https://naturespa.github.io/info1_IPass/`

教員用画面は `admin.html` です。設定した初期値を含む受験リンクを生成できます。設定を強制する機能ではなく、生徒が表紙から変更できます。

自動送信は行いません。生徒がステータスの「履歴を送信」を押したときだけ学校サーバへ提出します。受付日時・番号を生徒ブラウザにも残し、未送信の終了記録が増えたらステータスに案内します。教員が生徒の単回／履歴JSONをまとめて読み込み、公式正解で再採点し、分野別成績のCSVを出力します。A列=4桁番号、B列=氏名のCSV名簿（UTF-8／Shift JIS）と照合できます。成績・名簿は教員ブラウザのIndexedDBに保存し、ページを閉じても別ページの比較で利用できます。共有端末では注意し、公開リポジトリへ成績・名簿を置かないでください。

## 提出状況・生徒別比較

- `admin.html`：名簿と提出済み本チャレンジを照合し、全員／未提出だけの一覧、各回の提出状況、氏名不一致、練習のみ提出を表示。未提出者CSVも保存できます。「未提出」は未受験の判定ではありません。生徒端末に残る未送信記録は見えません。
- `compare.html`：管理画面とは別ページ。生徒を選び、総合・3分野の各回グラフ、初回／最新／最高、分野ごとの伸びを表示。比較条件の選択に対応し、練習・中断・異なる条件は伸びから除外します。
- 成績の平均は終了済み本チャレンジだけ。練習や中断終了は含めません。受験回数や出題難易度の違いがあるため、生徒の優劣を断定するものではありません。

## 学校サーバで提出を受け付ける

サーバPCにNode.js **22.13以降**を用意し、リポジトリをダウンロードしてください。npm依存パッケージはありません。

```bash
npm start
```

Windowsでは `C:\1nen\ipass` に一式を展開し、ルートの `start.bat` をダブルクリックします。`open_admin.bat` で教員画面を開けます。従来の `local-server/start.bat` も同じ起動処理を呼び出します。

- サーバPC：`http://localhost:3000/`
- 生徒は通常の公開サイトで受験し、ステータスに学校サーバのIPアドレスだけを入力 →「履歴を送信」。送信先は `http://IP:3000/api/submissions`。送信成功時に受付番号を表示。
- 既存の `info1_ddl_public` 提出サーバ（3003）と並行運用可能です。ITパスポート用はこのリポジトリのサーバ（3000）を起動してください。
- 教員：サーバPCで `http://localhost:3000/admin.html` →「学校サーバの結果を読み込む」
- 名簿：`C:\1nen\ipass\meibo.csv`（A列4桁番号、B列氏名）。管理画面で「名簿を確認」→追加／氏名変更／名簿から除外される人数を確認→「確認した名簿を取り込む」。既存成績と元CSVは変更しません。確認後にCSVが変わったら再確認を求めます。名簿ファイル取得APIは教員PCのlocalhostのみ許可します。
- 名簿の既定位置はプロジェクト直下の `meibo.csv`（Windows以外も同じ）。任意の配置先はサーバ起動時の環境変数 `ROSTER_CSV_PATH` で設定します。ブラウザからファイルの場所を自由に指定させません。手動CSV選択も残しています。GitHub Pagesだけでは教員PCの固定フォルダを直接読めないため、固定フォルダ方式は学校サーバ側の管理画面を使います。
- 保存先：`local-server/storage/ipass.sqlite`（Git管理対象外）。停止後にフォルダをコピーしてバックアップ。

提出された履歴全体を受付番号付きでSQLiteに保存し、終了済みの結果は公式解答で再採点して集計します。受験IDで集計の重複を防ぎ、再送でも件数を増やしません。提出前に受験開始・解答・進捗を送信するAPIは使いません。`https://naturespa.github.io` と同一オリジンからの提出を許可し、CORS／Private Networkのプリフライトに応答します。ブラウザから校内HTTPへの接続が制限される場合は、ローカルネットワークのアクセス許可や学校の設定を確認し、JSONファイル提出も利用してください。管理画面・結果取得APIはサーバPCのlocalhostだけに制限しています。端末間通信はHTTPのため、学校内の管理されたLAN向けです。インターネットへポートを直接公開しないでください。

## 保存・送信方式

- JSON：全解答・条件・日時・受験回数を残し、復元・再採点に使用。5回分なら十分小さく、今回の保存・提出の基本形式です。
- CSV：総合／分野別成績だけを軽く保存し、Excel集計に便利。全解答は含まれないため履歴復元には使えません。
- 生徒ブラウザ保存：手動ファイル操作をせずlocalStorageへ自動保存。練習回数には上限を設けませんが、端末の保存容量は有限です。定期的に履歴JSONを保存してください。教員側の多数の提出データはIndexedDBで管理します。
- 教員側はSQLite：提出をボタンで受け付けて一括集計でき、JSONファイルを1件ずつ管理する手間を減らします。受験履歴の管理元はブラウザです。

## 運用上の範囲

学習・授業での練習用です。静的問題データには正解が含まれ、受験者情報・開始時刻の本人確認や改ざん防止はありません。成績を用いる正式試験には、別途認証・出題制御・監督が必要です。得点は各問を等しく扱う正答率で、本試験のIRT評価点・合否と異なります。

問題は原本画像で、図表や選択肢を保持しています。OCRは参考単元の分類と点検候補の抽出にだけ使い、問題文や正解を自動で書き換えません。スクリーンリーダーで全文を読み上げることには対応していません。

## 問題・図表の点検と復習

- 全1,500問の公式正解、原本PDF30ファイルのSHA-256、保存された切り出し範囲と原本の画像一致、問題画像1,500問・参考資料85点の読込を自動点検しました。
- 長図表・複数ページ・OCR候補など36問を重点目視。7問に含まれていた元試験の「次の分野の案内」だけを表示範囲から除外し、問題文・図表・選択肢は残しました。画像原本は変更していません。全1,500問の意味内容を人が点検済みという主張ではありません。法制度・規格の現行性は別途確認が必要です。
- `audit.html`：問題ID／年度／参考単元で検索し、問題画像・公式正解・原本リンクを確認。この端末での目視確認記録も残せます。自動・OCRの未確認フラグは欠落の断定ではありません。
- 結果画面：誤答の多い参考単元、未解答数、復習する用語、具体的な2段階の復習と翌日の解き直しを表示。「この単元の問題を表示」「この誤答で復習練習」で対象を絞れます。復習練習は本チャレンジの回数を使いません。
- 参考単元はOCR／キーワードによる補助分類で、誤分類の可能性があります。目視補正は `scripts/reviewed-overrides.json`、点検の範囲と限界は `data/question-audit.json` に記録しています。

## 観点別の出題・成績と練習記録

- 本チャレンジは各回75問のうち知識・技能30問、思考・判断・表現45問です。5回で150問／225問となります。既存の分野比率、年度配分、重複制限を保ち、問題の分類を書き換えて比率を合わせることはしません。
- ステータスと結果に観点別の正答数を表示します。総合点は完了した対象回の観点別正答率を40点／60点に換算します。5回終了までは途中集計です。中断・取消し・旧条件の受験・練習は総合点に含めません。
- 全1,500問の観点はOCRから問題文の条件・図表・事例・計算を判別した一次分類です。教員の全問目視確認は未完了で、正式な成績用の確定分類ではありません。`aspect-review.html` で原本、判定理由、OCR、目視確認候補を確認できます。IPA公式分類ではなく、四肢択一問題だけで表現力そのものを測ることもできません。
- 年度別・ランダム等の練習は本チャレンジの成績から除外します。ステータスには実施回数、過去の誤答を解き直した問題数と正解できた問題数、苦手単元の初めて解く別問題の正答数を表示します。参考単元の自動分類に依存する参考記録で、主体性の評定を自動決定しません。対象がない場合の改善率は未集計です。
- 主体性の評価には、練習記録に加えて「目標→選んだ復習方法→結果→次の工夫」の短い振り返りを用いる運用を推奨します。振り返り入力機能は今回の追加対象に含めていません。
- 履歴送信は「教員から提出を求められた時のみ使用してください。」と案内します。

## 保存・提出・集計の追加機能

- 生徒画面の上部にブラウザ保存状態を表示します。失敗した場合は画面を閉じず、履歴JSONを保存してください。
- 提出日時・受付番号をブラウザに保存します。同じ内容の再送信は同じ受付番号を返し、受験ID単位でも成績を重複登録しません。送信成功後のブラウザ保存が失敗した場合は、受付番号を控える案内を表示します。
- 名簿照合には氏名不一致だけの表示を追加しました。
- `analytics.html` にクラス別・問題別の集計を追加しました。クラスは4桁番号の先頭2桁です。名簿と氏名が一致する提出記録を対象にします。クラスの最新平均は各生徒1件、問題正答率は未解答を含む解答件数が母数です。中断・取消しは除外します。問題別はモード・クラス・実施回・出題条件で絞り込め、CSV保存ができます。
- 復習の「別問題で確認テスト」は同じ参考分類の単元・分野から最大10問を出題します。復習元の受験で出た問題を除外します。確認テストは無制限の練習であり、本チャレンジ5回の対象外です。単元分類は参考分類で、難易度の同等性を保証するものではありません。
- 受験画面の不具合報告ボタンは削除しました。以前に保存した報告は履歴JSONと送信に含め、学校サーバPCの集計ページで確認できます。

### 教員による取消し・回数修正

学校サーバPCで `http://localhost:3000/admin.html` を開き、4桁番号・氏名・受験ID・理由を入力して「修正JSON」を発行します。受験IDは管理画面の結果一覧または生徒のステータスに表示しています。未提出の受験もIDを指定して取消せます。生徒がステータスで提出先IPを指定し、修正JSONを読み込むと、学校サーバで教員発行を確認したうえでブラウザ内の使用回数を1回戻します。同じ修正を繰り返しても回数は増えません。5回上限自体は変更しません。

元の受験と取消理由は残します。空いた実施回に再受験を保存し、取消した問題も過去の出題履歴として残します。取消した受験は成績比較・平均から除外します。教員側で発行しただけでは生徒端末は変わりません。未提出の通常の成績・解答は引き続き生徒ブラウザ内で管理します。修正に伴うサーバ接続で送るのは修正ファイルのみです。

### バックアップ・復元

管理画面の「教員データを一括バックアップ」で成績・名簿を保存します。学校サーバPCから実行すると、サーバの成績・受付履歴・不具合報告・修正履歴・修正ファイル検証用データも一緒に保存します。GitHub Pages上で実行すると、教員ブラウザの成績・名簿だけが対象です。バックアップは氏名・成績・教員用の修正検証データを含むため、教員管理用として保管してください。名簿の元CSVはこのバックアップには含みません。

復元は形式と成績を確認してから、成績・名簿を置き換えます。先に現状のバックアップを保存してください。サーバ部分の復元は学校サーバPCだけで行えます。サーバDBの復元は1トランザクション、ブラウザ成績・名簿の復元も1トランザクションで処理します。この2つは別の保存先なので、サーバ成功後にブラウザ復元が失敗した場合は、同じバックアップで再実行してください。

最新版を学校サーバPCにコピーし、サーバを再起動してください。`local-server/storage` 内の既存データは引き継ぎます。GitHub PagesではNode.jsの受信・教員修正・サーバ復元機能は動きません。

履歴JSONと履歴送信には `assessment` として観点別の各回・総合集計、練習の改善記録、一次分類の状態、集計条件を含めます。元の受験履歴も残し、従来の読込形式に対応します。教員側は元の解答を再採点し、追加の集計値を成績の正解として信用しません。分類確認画面の「全1,500問の分類JSONを保存」は、表示フィルターに関係なく全問の分類・判定理由・OCR・出典と一次分類の限界を出力します。

## 教員用パスワード

教員機能は学校サーバPCの `http://localhost:3000/admin.html` で利用します。最新版をコピーして学校サーバを再起動し、初回に8文字以上のパスワードを設定してください。次回からはログインが必要です。公開GitHub Pagesの教員用リンクは学校サーバでの利用案内だけを表示します。静的公開サイトにパスワード照合を置いても認証を回避できるため、公開サイト上では教員機能を起動しません。

設定したパスワードは学校サーバのDBにsalt付きscryptハッシュで保存し、公開ファイル・URL・成績バックアップに含めません。認証はHttpOnly・SameSite=StrictのCookieで最長8時間、サーバ再起動で失効します。5回連続の誤入力で1分間ログインを制限します。学校サーバの成績・名簿・報告・修正・バックアップAPI、各教員画面はログインが必要で、従来通りサーバPCのlocalhostからのみ利用できます。生徒の受験・履歴提出・教員修正の確認には教員ログインを求めません。

各教員画面の「パスワード変更・ログアウト」から変更や終了ができます。パスワード変更時は既存セッションを失効させます。ログアウトは他の教員画面タブにも通知し、画面は定期的にログイン状態を確認します。ブラウザ内の教員データは端末の保存データであり、この認証によって暗号化されるわけではありません。GitHub Pages側で保存済みの教員ブラウザデータはlocalhost側に自動移行されません。保存済みの教員バックアップJSON／提出JSONを学校サーバ側の教員画面で取り込んでください。

パスワードを忘れた場合は学校サーバを停止し、プロジェクトのフォルダで `node local-server/server.mjs --reset-teacher-password` を実行します。次のログイン画面で新しいパスワードを設定し、設定後は通常の起動方法に戻してください。これは教員認証だけを初期化し、成績・名簿・提出履歴を削除しません。`local-server/storage` は引き続き既存データごと保管します。

## 画面移動と本チャレンジの全画面表示

各ページの上下に「表紙に戻る」、教員の子ページには「教員画面に戻る」を追加しました。生徒の操作説明・開始前・受験中・結果にも表紙／ステータスへ移動できるボタンを置き、表紙へ戻るたびに再開ボタンの表示を更新します。受験中の移動は保存確認を行い、保存失敗時は移動しません。使用回数を増やさず再開でき、移動中も制限時間は進み続けます。

本チャレンジは開始・再開のクリックでFullScreen APIを呼び、全画面表示に成功してから開始します。練習は通常表示です。本チャレンジの提出・時間終了・中断終了で通常表示に戻ります。全画面の解除、別タブ表示、ウィンドウのフォーカス離脱を検知した場合は受験画面を操作不可にし、全画面に戻るボタンを表示します。イベントの種類と時刻を履歴・結果JSONの `fullscreenEvents` に残しますが、移動先サイトは取得しません。この記録はブラウザで検知できた参考記録であり、不正の断定や完全な監視を保証しません。

WebサイトはEsc／F11、OSのアプリ切替、別の端末の使用を禁止できません。全画面表示は他サイトへのアクセスを完全に遮断する仕組みではありません。完全な制限は学校管理端末のキオスク・試験用アプリ等で別途設定する必要があります。全画面非対応／拒否の場合、本チャレンジは開始せず案内を表示し、回数を使用しません。実際の全画面表示と復帰の動作は、使用する学校のブラウザ・端末で確認してください。

## クラス別提出状況・授業改善と発表用統計

提出状況は番号先頭2桁のクラスで絞り込めます。未提出者CSVも選択クラスを反映します。クラス間比較では比較する出題条件を選び、各生徒の最新1件の平均、同じ生徒の初回と最新の平均差、人数を確認します。クラス名ボタンで生徒一覧を切り替え、クラスの統計ページへ進めます。

`statistics.html` は認証済み教員用の統計ページです。クラス、出題条件、期間（終了日時・日本時間）、集計名、問題／単元の最小解答件数を設定できます。集計名だけでは年度の対象者を変えません。次年度に名簿を更新する前に、当該年度の統計と教員バックアップを保存してください。

表示・出力には、最新得点の平均／中央値／母標準偏差／分布、各回平均、同一生徒の初回→最新と第1回→第5回の差、分野／一次分類の観点別成績、条件を満たした5回総合、練習の再挑戦・改善、参考単元と問題の正答率を含みます。CSV・JSONは匿名の集計で氏名／生徒番号／受験IDを含めず、SVGはクラス比較・各回推移・得点分布の図表です。印刷からPDFにも保存できます。

名簿照合対象外、中断、取消し、同一生徒同一回の重複を整理した件数も表示します。未提出者を0点とせず、出題条件を混ぜません。各回平均と同じ生徒の伸びは別集計です。抽選問題の難易度差や参考単元の誤分類を含むため、伸びだけで授業の因果効果や主体性を判定しません。新しいサーバ提出は管理画面で取り込んでから統計を再読込してください。
